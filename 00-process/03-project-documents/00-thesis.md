# Investment Thesis: Bypassing the procurement in B2B - Friction Shift in usage behavior

## The Argument

Traditional software/app adoption is slow due to middle layers increasing timeline at every step be it procurement, finance, security etc before any one on the end user side can see any value

We want to find opportunity that takes this problem and mitigate it by following last steps first, so instead of:

> Procurement -> Approval -> Deployment -> User Value

We are looking for:

> User Value -> Repeated Use -> Team Adoption -> Enterprise Need -> Procurement

The companies we care about should:

    - solve a real daily or frequently occuring employee problem
    - be easy to start using
    - no approval gates required
    - become part of an important workflow
    - have a growth opportunity from single user to teams either via collaboration or sharing a common part

Reversing the adoption chain is just a way of proving the product value and there must be a clear path to reach procurement

## The Evidence

The [thesis research summary](../_intermediate-files-outputs/03-thesis-research-summary.md) shows the procurement pipeline is slow and includes friction before the end user can see the actual value

While SaaS has reduced adoption friction via browser access, self-service usage, free trials let employees start using tools without waiting for central deployment and procurement

Shadow IT proves that employees use tools outside formal processes when those tools help work faster

AI makes this even stronger because many AI tools are browser-based and cheap or free to start and useful to one person immediately

The important points for early adoption are:

    - adoption friction: can I start using it?
    - purchasing friction: can my company officially buy it?

Research shows that the strongest products minimize or remove the first problem and deal with the second after usage is established

However individual usage is not enough there should be some reason the product expands into a team or enterprise need, such as collaboration, shared data, governance, security, or group billing

Frequency matters however importance matters too as a product used monthly can still be very valuable if the workflow is important

## Assumptions and Limitations

### Assumptions:

* employees can increasingly adopt software directly
* low adoption friction can create an increase in distribution
* repeated usage can be converted to internal demand
* team usage is more valuable than individual usage
* public data is sufficient for initial triage

### Limitations:

* enterprise security can block adoption
* easy adoption can create compliance risk
* single user products may never expand
* usage does not guarantee buying
* procurement is only delayed
* public startup data can be incomplete or self-reported
* current batch membership shows freshness and not usage
* missing data should stay unknown and not a failure
* the score measures against thesis
